# Детекция упавших людей на изображениях с камер видеонаблюдения

YOLO11s находит людей на кадре и определяет, кто из них упал. Сервис FastAPI принимает один кадр в формате JPEG или PNG и возвращает рамки вокруг найденных упавших людей.

## Датасет FPDS

Исходные кадры и разметка лежат в `FPDS_dataset/FPDS/`. В разметке FPDS `-1` означает человека без падения, а `1` — упавшего человека. Скрипт `prepare_data.py` перекодирует эти классы в `0` (`person`) и `1` (`fallen_person`). Вместо четырёх границ рамки в пикселях он записывает координаты центра, ширину и высоту рамки в долях от размера изображения.

| Часть | Папки FPDS | Кадры |
| --- | --- | ---: |
| Обучение | `split1`, `split2` | 723 |
| Валидация | `split3` | 366 |
| Тест | `split4`–`split8` | 973 |

Каждый `split` целиком попадает в одну часть. Так соседние кадры из одной папки не смешиваются между обучением и проверкой. Кадры без людей остаются в наборе с пустой разметкой.

## Подготовка и обучение

Команды для PowerShell из корня проекта. Нужен Python 3.13. Установка PyTorch ниже рассчитана на процессор.

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install torch==2.15.0 torchvision==0.29.2 --index-url https://download.pytorch.org/whl/cpu
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe prepare_data.py
.\.venv\Scripts\python.exe train.py
```

`prepare_data.py` создаёт `data/images/` и `data/labels/`. Пути и имена классов описаны в `data.yaml`.

`train.py` начинает с готовых весов YOLO11s и дообучает модель на FPDS. При первом запуске Ultralytics скачивает `yolo11s.pt`. По умолчанию скрипт делает 12 эпох, использует входной размер 320 × 320 пикселей и оставляет первые 10 слоёв модели замороженными. По валидации выбирается лучший набор весов, затем скрипт оценивает его на тесте.

- `weights/best.pt` — обученные веса для сервиса.
- `runs/fpds/results.csv` — показатели по эпохам.
- `runs/fpds/test/` — матрица ошибок и графики для теста.

При повторном обучении Ultralytics создаёт новую папку в `runs/`. Датасет, веса и результаты обучения хранятся локально.

## Результат на тесте

После 12 эпох модель проверена на 973 кадрах из `split4`–`split8`.

| Класс | AP50 | AP50–95 |
| --- | ---: | ---: |
| Человек без падения | 0,904 | 0,498 |
| Упавший человек | 0,965 | 0,543 |
| Среднее (mAP) | 0,934 | 0,520 |

AP50 оценивает обнаружение объектов, когда пересечение найденной и правильной рамок составляет хотя бы 50% от площади их объединения. AP50–95 усредняет результат по порогам пересечения от 50% до 95%, поэтому точность положения рамки влияет на него сильнее.

## Запуск в Docker

Запусти Docker Desktop. Собери образ и подключи папку с обученными весами.

```powershell
docker build -t fpds-yolo11s .
docker run --rm -p 127.0.0.1:8000:8000 --mount "type=bind,source=$($PWD.Path)\weights,target=/app/weights,readonly" fpds-yolo11s
```

Открой <http://localhost:8000/docs>. В `POST /detect` выбери **Try it out**, загрузи изображение и нажми **Execute**. Сервис загружает веса один раз при запуске. `GET /health` показывает, что сервис готов принимать запросы.

Для проверки подойдут два кадра из `data/images/test/`. На `split4_025.png` сервис нашёл упавшего человека, на `split4_001.png` вернул пустой список.

`has_fall` сообщает, есть ли хотя бы одна детекция. Каждая запись в `detections` содержит класс `fallen_person`, уверенность `confidence` и рамку `box` в пикселях `[x1, y1, x2, y2]`. Порог уверенности по умолчанию равен `0.25`. Его можно поменять параметром `confidence` в запросе.

Документация к модели, разметке и загрузке файлов. [YOLO11](https://docs.ultralytics.com/models/yolo11/), [разметка YOLO](https://docs.ultralytics.com/datasets/detect/), [загрузка файлов в FastAPI](https://fastapi.tiangolo.com/tutorial/request-files/).
