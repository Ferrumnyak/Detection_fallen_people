# Детекция упавших людей на изображениях с камер видеонаблюдения

В этой курсовой я дообучил YOLO11s на датасете FPDS v1. На вход подаётся один кадр в JPEG или PNG. Если модель находит упавшего человека, FastAPI возвращает координаты рамки и уверенность модели. Как я готовил данные, обучал модель и разбирал её ошибки, описано в [отчёте](REPORT.md).

## Как запустить

Для запуска нужен Docker с Linux-контейнерами и Docker Compose. Модель работает на процессоре. При первой сборке нужен интернет, чтобы Docker скачал базовый образ и библиотеки.

Распакуйте архив курсовой и откройте терминал в папке с `compose.yaml`. В архиве уже есть обученные веса `weights/best.pt` и результаты эксперимента в `tracking/`.

```powershell
docker compose up -d --build --wait api tracker
```

## Как проверить на фотографии

Откройте [Swagger](http://localhost:8000/docs) и выберите `POST /predict`. Нажмите **Try it out**, загрузите фотографию в поле `file` и нажмите **Execute**. Для проверки можно взять [кадр с падением](examples/fall.jpg) и [кадр без людей](examples/empty.jpg).

Те же запросы можно отправить из PowerShell. Первый проверяет, что API уже загрузил модель и отвечает, второй отправляет кадр на распознавание.

```powershell
curl.exe http://localhost:8000/health
curl.exe -F "file=@examples/fall.jpg" http://localhost:8000/predict
```

В Linux и macOS используйте `curl` вместо `curl.exe`. По умолчанию порог уверенности равен `0.25`. Его можно изменить, например запросом к `/predict?confidence=0.4`.

`has_fall` показывает, нашла ли модель хотя бы одного упавшего человека. В `detections` лежат найденные рамки. У каждой есть класс `fallen_person`, уверенность `confidence` и координаты `[x1, y1, x2, y2]` в пикселях. Когда модель не находит ни одной рамки этого класса, ответ выглядит так.

```json
{"has_fall": false, "detections": []}
```

При ошибке её описание будет в поле `detail`. Код `400` означает, что файл не удалось открыть как JPEG или PNG. `413` означает, что превышен лимит на размер файла или число пикселей, а `422` — что пропущен файл или задан неверный порог.

## Где посмотреть результаты

Параметры обучения, графики по эпохам и оценки на тестовых кадрах есть в [финальном запуске MLflow](http://localhost:5000/#/experiments/1/runs/5ea928d9a3e64a0fa66c7ff8be312fcd) в эксперименте `FPDS-YOLO11s`. Во вкладке **Artifacts** можно посмотреть разбиение данных, результаты теста и скачать `best.pt`. Номер запуска и хеш файла весов записаны в `weights/run.json`. Тот же хеш указан в MLflow в теге `weights_sha256`.

## Как повторить обучение

Распакуйте `FPDS_dataset.zip` в папку проекта. В результате должен появиться путь `FPDS_dataset/FPDS/split1/`. Затем выполните три команды. Они запускают MLflow, готовят кадры и разметку, а потом запускают обучение. [Страница авторов FPDS](https://gram.web.uah.es/data/datasets/fpds/index.html)

```powershell
docker compose up -d --build --wait tracker
docker compose run --rm --build train python prepare_data.py
docker compose run --rm train
```

Скрипт `prepare_data.py` сохраняет изображения и разметку в `data/`, а число кадров по выборкам — в `data/dataset.json`. На `split1` и `split2` модель учится, по `split3` выбираются лучшие веса, а `split4`–`split8` используются для итоговой проверки.

Для обучения использую исходные веса `runs/yolo11s.pt`. Они лежат в архиве, а если файл убрать, Ultralytics скачает его. По умолчанию обучение идёт 12 эпох с размером входа 320 × 320. `train.py` выбирает лучшие веса по mAP50–95 на валидации, проверяет их на тесте и сохраняет в `weights/best.pt`.

Если API уже работает, выполните `docker compose restart api`, чтобы он загрузил новые веса. Остановить проект можно командой `docker compose down`. Веса, результаты в `runs/` и история MLflow в `tracking/` останутся в папке проекта.
