# Детекция упавших людей на изображениях с камер видеонаблюдения

YOLO11s находит упавших людей на одном кадре. FastAPI принимает JPEG или PNG и возвращает координаты рамок и оценки уверенности. В [отчёте](REPORT.md) описаны данные, эксперимент и ошибки модели.

Для запуска нужен Docker с Linux-контейнерами и командой `docker compose`. Модель обучается и работает на процессоре. При первой сборке нужен интернет для загрузки базового образа и библиотек.

## Запуск с готовыми весами

В архиве для сдачи есть `weights/best.pt`, `weights/run.json` и данные локального трекера в `tracking/`. Распакуй архив и запусти контейнеры из его корня.

```powershell
docker compose up -d --build --wait api tracker
```

- Открой [интерфейс API](http://localhost:8000/docs), выбери `POST /predict`, нажми **Try it out** и загрузи кадр.
- Открой [MLflow](http://localhost:5000) и выбери эксперимент `FPDS-YOLO11s`. В запуске видны параметры, графики по эпохам и итоговый тест. В **Artifacts** лежат `weights/best.pt`, разбиение, графики и метрики.

Готовые веса из архива получены в запуске `5ea928d9a3e64a0fa66c7ff8be312fcd`. [Открыть запуск в MLflow](http://localhost:5000/#/experiments/1/runs/5ea928d9a3e64a0fa66c7ff8be312fcd)

`GET /health` возвращает `{"status":"ok"}` после загрузки модели. Передавай изображение в поле `file` формы `multipart/form-data`.

```powershell
curl.exe http://localhost:8000/health
curl.exe -F "file=@examples/fall.jpg" http://localhost:8000/predict
```

В Linux или macOS те же команды выполняются через `curl`. Порог уверенности можно задать в адресе, например `/predict?confidence=0.4`. По умолчанию он равен `0.25`.

В ответе `has_fall` показывает, есть ли хотя бы одна детекция. Каждая запись в `detections` содержит класс `fallen_person`, оценку `confidence` и координаты рамки `[x1, y1, x2, y2]` в пикселях. На кадре без падения список пуст.

```json
{"has_fall": false, "detections": []}
```

Повреждённое или неподдерживаемое изображение возвращает `400`, слишком большой файл — `413`, отсутствие поля `file` или неверный порог — `422`. Подробности приходят в поле `detail`.

## Подготовка данных и обучение

1. Распакуй `FPDS_dataset.zip` из комплекта для сдачи в корень проекта. Должен появиться путь `FPDS_dataset/FPDS/split1/`. В проекте использована **FPDS Version 1**. [Страница авторов FPDS](https://gram.web.uah.es/data/datasets/fpds/index.html)
2. Запусти трекер, подготовь кадры и обучи модель.

```powershell
docker compose up -d --build --wait tracker
docker compose run --rm --build train python prepare_data.py
docker compose run --rm train
```

Исходные `runs/yolo11s.pt` входят в комплект. При отсутствии файла Ultralytics загрузит его. Скрипт подготовки создаст `data/images/`, `data/labels/` и сводку `data/dataset.json`. Исходные `split1` и `split2` идут в обучение, `split3` — в валидацию, `split4`–`split8` — в тест.

Дообучение занимает 12 эпох при размере входа 320 × 320. По валидационной mAP50–95 скрипт выбирает лучшие веса, затем проверяет их на тесте и сохраняет `weights/best.pt`. Веса, результаты в `runs/` и база MLflow в `tracking/` остаются в каталоге проекта после удаления контейнеров.

После обучения перезапусти ранее запущенный API командой `docker compose restart api`. ID запуска и SHA-256 файла весов записаны в `weights/run.json`. В MLflow этот же хеш указан в теге `weights_sha256`, а файл доступен в **Artifacts → weights**. Так можно проверить, какие именно веса использует сервис. Команда `docker compose down` останавливает контейнеры.
